# Data Processing — SME Retail Churn Prediction

Research pipeline for a thesis on churn prediction in non-contractual SME
retail. The study runs a 2×4 factorial experiment crossing two churn
**labeling schemes** (fixed-threshold vs. category-level dynamic) with four
model **updating strategies** (static, periodic, rolling-window,
drift-triggered), evaluated prequentially over monthly batches on
transaction data from Kingdee's retail/business-management platform. See
`thesis/chap03.tex` for the full research design and `pipeline/PIPELINE.md`
for the step-by-step pipeline contract.

## Repository Layout

| Path | Contents |
|---|---|
| `pipeline/` | All pipeline scripts (profiling → cleaning → feature engineering → labeling → dataset assembly → split/drift → tuning → experiment → metrics) and shared modules (`experiment_config.py`, `drift_utils.py`, `strategies.py`, `metrics.py`). Run order and I/O contracts: `pipeline/PIPELINE.md`. |
| `sale_data/` | Raw input CSVs (`srv_sales.csv`, `srv_saleitems.csv`, `industry_servereid.csv`) and field glossary (`sale_data/README.txt`, Chinese field names). |
| `profiling_output/` | Intermediate artifacts, organized by pipeline step (`step1_profiling` … `step7_split_drift`), plus `_legacy`. |
| `experiment_output/` | Final experiment artifacts: tuned hyperparameters, frozen feature set, per-batch/per-config metrics, predictions (`predictions/<maturity_mode>/<strategy>/`), retrain log. |
| `docs/` | Thesis-supporting documents: data requirements/cleaning/preprocessing plans, data report, consolidated preprocessing decision log, weekly/step reports (`docs/reports/`), archived report tooling (`docs/archive/`). |
| `tests/` | Pytest suite for shared pipeline modules (drift utils, experiment config, metrics, strategies, TSCV folds). |
| `thesis/` | LaTeX thesis chapter(s) and supporting data/figures. |
| `llm_prior_threshold_trial/` | Standalone side experiment testing whether LLM-elicited merchant knowledge can inform the dynamic churn threshold. Isolated from the main pipeline — see its own `README.md`. |
| `utils/` | One-off analysis scripts (e.g. `analyze_zero_payment.py`). |

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Requires `pandas`, `pyarrow`, `numpy`, `scikit-learn`, `xgboost`, `pytest`
(see `requirements.txt` for pinned minimum versions). Python 3.13 is used in
development.

## Running the Pipeline

Pipeline steps are numbered only in `pipeline/PIPELINE.md` (filenames no
longer carry step prefixes). Run scripts from the repo root, in order:

1. `python pipeline/data_profiling.py` — profile raw data (chunked; input is ~7.2 GB)
2. `python pipeline/remove_outliers.py`, `detect_test_accounts.py`, `handle_returns.py`, `remove_orphans.py` — cleaning sequence (run in this order)
3. `python pipeline/temporal_structuring.py` — monthly batching + observation/label window split
4. `python pipeline/feature_engineering.py` — build the 25-feature matrix
5. `python pipeline/label_construction.py` — build L1 (fixed) and L2 (dynamic) churn labels
6. `python pipeline/dataset_assembly.py` — merge into `dataset_final.parquet`
7. `python pipeline/train_eval_split.py`, `drift_baselines.py`, `preprocessing_log.py` — split, drift baselines, consolidated decision log
8. `python pipeline/eval_labels.py`, `hyperparameter_tuning.py`, `feature_set_comparison.py`, `run_experiment.py`, `compute_metrics.py` — shared eval label, tuning, feature-set comparison, the 8-configuration prequential run, and final metrics

Each script's docstring documents its exact input/output contract. Runs are
deterministic (`random_state=42`); `run_experiment.py` is **not** resumable
mid-run — rerunning it redoes all 8 configurations and overwrites
`experiment_output/predictions/` and `retrain_log.csv`.

## Tests

```bash
pytest tests/
```

Covers the shared modules used across pipeline steps: drift utilities
(PSI/binning), experiment config invariants, metrics, update strategies, and
leakage-safe TSCV fold construction.

## Notes

- `sale_data/` and most of `profiling_output/` / `experiment_output/` are
  large/generated — check `.gitignore` before adding new raw or
  intermediate files.
- `docs/preprocessing_log.md` is the single consolidated record of every
  cleaning/exclusion decision and is generated by
  `pipeline/preprocessing_log.py` — don't hand-edit it.
